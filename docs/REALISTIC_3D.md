# リアルなキャラクターをゲームの世界で動かすには

MOONBOUNDの現在のモデルは、基本形状から組み立てたプロトタイプです。今回、顔への肖像画像の投影を撤去し、目・鼻・口を立体形状に戻しました。歩行は移動距離と連動し、攻撃は構え・振り・戻しを滑らかにつなぎます。移動と攻撃の向きが争う処理、敵の跳ね、被弾時の拡大、回避の瞬間移動を修正。攻撃ダメージは入力直後ではなく剣を振るタイミングに合わせます。全LODで同じ姿勢を更新し、切り替え時の姿勢飛びを防ぎます。髪とマントは振れ幅を制限した表現です。

この修正は、モンスターハンター等と同等の品質になったという意味ではありません。精細なモデル制作と、移動・攻撃を組み合わせるアニメーションシステムが必要です。

## 1. 立体モデルを作る

Blender、Maya、ZBrush等で頭部・全身・衣装を制作します。元の人物像に合った正面・横・背面の設定画を用意し、眼窩、鼻、顎、耳、髪の立体形状を決めます。高精細な造形からゲーム向けメッシュへリトポロジーし、肘・膝・肩が曲がった際に崩れない面構成にします。

一枚のイラストを頭部へ投影する方法では、横顔や後頭部を作れません。画像に描かれた光と実際の照明が重なり、顔が貼り付けたように見えます。イラストはデザイン資料として使い、立体モデルとそのUVに合わせて素材を制作する必要があります。

## 2. PBRの素材を作る

Substance 3D Painter等で、UVに対応したBase Color、Normal、Roughness、Metallic等を作ります。Base Colorには強い影やハイライトを焼き込まず、光はゲーム側で計算します。Normal Mapは高精細な造形からベイクし、傷・革目・布目を表現します。

肌には皮下散乱（SSS）、眼球には角膜の反射と涙の縁、髪には専用の透過・異方性反射が効果的です。これらは素材ごとのシェーダー設計が必要で、面数を増やすだけでは得られません。

## 3. 骨格とスキニングを作る

全身にボーンを配置し、メッシュの頂点に適切なウェイトを設定します。肩、股関節、肘、膝の変形を確認し、必要に応じて補正用の形状を用意します。顔にはBlendshape / Morph Targetや顔専用ボーンを作り、瞬き、視線、表情を制御します。

24人を展開する場合は、共通の骨格を使い、顔・体格・髪・衣装を変える方が制作とモーション共有を管理しやすくなります。ただし体格差には補正が必要です。

## 4. モーション素材を作る

待機、歩行、走行、旋回、抜刀、攻撃、回避、被弾、死亡を手付けやモーションキャプチャで制作します。腕・脚だけを周期的に動かすと、体重移動や予備動作が足りません。攻撃には構え、溜め、振り抜き、戻しを含めます。

素材のライセンスは、ゲーム配布とリポジトリでの配布の両方について確認する必要があります。

## 5. 動きを自然につなぐ

Animation State MachineとBlend Treeで、停止から歩行、歩行から攻撃などを滑らかにつなぎます。上半身の攻撃と下半身の移動を別レイヤーで扱い、必要な場面だけボーンに重ねます。

Root Motionを使う場合はアニメーション側の移動量と当たり判定を同期します。使わない場合も、移動速度と歩幅・再生速度を合わせます。足の接地IKは最後の補正として使い、良い歩行モーションの代わりにはしません。

## 6. 物理と戦闘判定を同期する

キャラクターの移動はカプセル形状等のコライダーで地面・壁と接触させます。髪・衣装の物理は固定時間刻みで計算し、身体との衝突、減衰、可動範囲を設定します。Ragdollは被弾・死亡などに限定して、アニメーションから滑らかに切り替えます。

武器の当たり判定は振り始めから振り終わりの有効区間に合わせます。攻撃の瞬間に敵へ方向転換させたり、ダメージと剣の動きを別々に進めたりすると違和感が出ます。

## 7. 光と画面を整える

HDR環境光、影、露出、トーンマッピング、色空間を統一します。肌、鎧、髪が同じ光に反応することが重要です。背景との色合わせ、時間方向のアンチエイリアス、必要な範囲のポスト処理も行います。

## 8. スマートフォン向けに最適化する

LOD、アニメーション更新頻度、描画距離、影の品質、テクスチャ解像度を調整します。ブラウザではglTF / GLB、KTX2 / Basisのテクスチャ圧縮、Meshopt / Dracoのメッシュ圧縮が選択肢です。面数だけでなく、Draw Call、GPUメモリ、透明な髪の重なり、スキニング、影の描画コストを実機で測定します。

LODは精細なモデルを軽く表示する仕組みです。元のモデルやモーションを高品質にする仕組みではありません。

## このゲームでの現実的な進め方

最初に1人だけ、本格的なモデルと「待機・歩行・攻撃・回避」を完成させます。正面・横・背面、光を変えた状態、停止と再開、旋回、攻撃終了、スマホでの動作を確認し、それから共通骨格で他のキャラクターへ展開します。

ブラウザ版はThree.js / Babylon.jsで継続できます。家庭用ゲームに近い複雑な表現を優先するならUnreal Engine等、スマホの実機アプリを中心にするならUnity等も候補です。エンジンを変えても、精細なモデルと良いモーション素材の制作は必要です。
